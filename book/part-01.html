Part I: The Craft

Part I: The Craft

The nouns, before the story (plain prose; skip freely if you already run Spring)

Bean: an object whose construction and lifetime Spring manages. You declare what your class needs; the container builds it and hands it in. The container (ApplicationContext): the registry that scans your code for annotated classes, constructs each bean (once, by default), injects its dependencies, and serves it wherever it's needed. Dependency injection: a class does not create its collaborators with new; it receives them. In this book it always receives them through constructor parameters, into final fields. Controller: a bean whose methods answer HTTP requests. @GetMapping("/hello") on a method routes GET /hello to it, and in a @RestController the value the method returns becomes the response body. Jackson: the JSON library Spring Boot uses by default. When a controller returns a record or an entity, Jackson writes it to the response as JSON (serialization) by calling its getters. Entity: a class mapped to a database table. DTO: a plain object (usually a record) that carries data across a boundary, such as your API. JPA (Jakarta Persistence): the standard Java API for mapping classes to database tables and for loading and saving their objects. Hibernate: the library that implements JPA, and the implementation Spring Boot's JPA starter brings in. Session: the object through which an application uses Hibernate. It loads and saves entities and holds the set of entities it is currently managing, which JPA calls the persistence context. A session is opened, used and closed. Lazy loading: a fetch strategy. An association (a field that refers to another entity, or to a collection of them) is loaded on first access rather than up front, and that first access needs the session to be open. Proxy (a preview): the container may hand back a wrapper around your bean that adds behavior such as transactions, security and caching. Chapter 3 looks at it up close. @Transactional: an annotation that puts a method inside a transaction, the all-or-nothing unit of database work. A proxy around the bean opens the transaction before the method runs and commits it when the method returns.

A first Spring Boot application fits in one source file: one class starts the container, one class is a bean, and one controller receives that bean through its constructor. Start it, request http://localhost:8080/hello?name=Kenza, and the response is Hello, Kenza.

@SpringBootApplication                    // scan this package, auto-configure, start the container
public class FirstBeanApp {
    public static void main(String[] args) {
        SpringApplication.run(FirstBeanApp.class, args);
    }
}

@Component                                // a bean: Spring constructs it once and hands it out
class Greeter {
    String greet(String name) { return "Hello, " + name; }
}

@RestController                           // also a bean; its dependency arrives through the constructor
class HelloController {
    private final Greeter greeter;
    HelloController(Greeter greeter) { this.greeter = greeter; }

    @GetMapping("/hello")
    String hello(@RequestParam(defaultValue = "world") String name) { return greeter.greet(name); }
}
